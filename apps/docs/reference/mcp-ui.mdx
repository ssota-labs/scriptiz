Scriptiz exposes **two related layers**:

1. **Tool results (JSON)** — built with `@scriptiz/mcp-ui` and returned from the tools below. Hosts that only show text/JSON can still use this.
2. **[MCP Apps](https://modelcontextprotocol.io/extensions/apps/overview)** — tools declare `_meta.ui.resourceUri` → `ui://scriptiz/app`. The MCP server answers `resources/read` with **`text/html`** (placeholder or the Vite build under `packages/mcp-ui/web/dist` when `SCRIPTIZ_MCP_UI_DIST` is set). **ChatGPT** and other hosts render that HTML in a **sandboxed iframe** and use the standard `ui/*` bridge ([OpenAI notes](https://developers.openai.com/apps-sdk/mcp-apps-in-chatgpt)).

For **ChatGPT**, the same URI may also appear as `_meta["openai/outputTemplate"]` (compatibility alias).

## `get_video_transcript_view`

**Video** resource + timed segments (and embed URL) payload.

**Input:** `resourceId`, `language?`, `cursor?`, `limit?` (default 500, max 2000)

**Errors:** `NOT_FOUND`, `INVALID_RESOURCE` (not a video), `NO_TRANSCRIPT`, `INVALID_CURSOR`, `BUILD_UI_PAYLOAD` (build failure), `VALIDATION_ERROR`

## `get_list_view`

List + each item’s **resource** and **transcript language** tags.

**Input:** `{ "listId": string }`  
**Errors:** `NOT_FOUND`

## `get_job_status_view`

**Input:** `{ "jobId": string }` (same `jobId` schema as other tools)

**Success:** Job + optional resource metadata (payload from `@scriptiz/mcp-ui` `buildJobStatusView`)  
**Errors:** `JOB_NOT_FOUND`, `VALIDATION_ERROR`

## UI-only codes (summary)

| Code | Description |
|------|-------------|
| `INVALID_RESOURCE` | Transcript view requires `type: video` |
| `BUILD_UI_PAYLOAD` | Internal builder threw |
| `NOT_FOUND` / `JOB_NOT_FOUND` | Resource or job missing |

## Local try-out

- **JSON / layout:** `pnpm dev:ui` → Vite app in `packages/mcp-ui/web` (no full MCP host required).
- **MCP Apps iframe:** use a host that implements MCP Apps; run `pnpm --filter @scriptiz/mcp-ui run build:web` and set `SCRIPTIZ_MCP_UI_DIST` to `packages/mcp-ui/web/dist`. Full `ui/*` integration is tracked as follow-up work.
