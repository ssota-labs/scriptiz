---
title: MCP UI
description: MCP Apps (ui://), shared HTML, and ordinary tool JSON — no separate view tools
---

Scriptiz exposes **two related layers**:

1. **Tool results (JSON)** — domain tools (`get_timed_transcript`, `get_list_contents`, `get_extraction_status`, `get_content`, etc.) return plain JSON. Layout helpers (`buildVideoTranscriptView`, …) live in `@scriptiz/mcp-tools/ui` for demos, tests, or hosts that compose views client-side; they are **not** separate MCP tools.
2. **[MCP Apps](https://modelcontextprotocol.io/extensions/apps/overview)** — **every** registered tool includes `_meta.ui.resourceUri` → `ui://scriptiz/app`. The MCP server answers `resources/read` with **`text/html`** (placeholder or the Vite build under `packages/mcp-tools/web/dist` when `SCRIPTIZ_MCP_UI_DIST` is set). **ChatGPT** and other hosts render that HTML in a **sandboxed iframe** and use the standard `ui/*` bridge ([OpenAI notes](https://developers.openai.com/apps-sdk/mcp-apps-in-chatgpt)).

For **ChatGPT**, the same URI may also appear as `_meta["openai/outputTemplate"]` (compatibility alias).

## Typical data for a transcript UI

Use **`get_timed_transcript`** (and **`get_content`** for resource metadata) instead of a dedicated view tool. Pagination: **`nextCursor`** on the transcript response.

## Typical data for a list UI

Use **`get_list_contents`** for list metadata, items, and resolved resources.

## Typical data for job status

Use **`get_extraction_status`** with `{ "jobId": string }`.

## Local try-out

- **JSON / layout:** `pnpm dev:ui` → Vite app in `packages/mcp-tools/web` (no full MCP host required). Paste sample JSON built with `@scriptiz/mcp-tools/ui` or raw tool output.
- **MCP Apps iframe:** use a host that implements MCP Apps; run `pnpm --filter @scriptiz/mcp-tools run build:web` and set `SCRIPTIZ_MCP_UI_DIST` to `packages/mcp-tools/web/dist`. Full `ui/*` integration is tracked as follow-up work.
